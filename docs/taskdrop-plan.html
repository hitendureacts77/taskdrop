TaskDrop

“If you can ask for it, someone can drop it.”

A unified reverse-marketplace: a Poster publishes an open-ended request with a benchmark price, Workers pitch and negotiate quotes, and funds sit in escrow until the work is verified. One Android app for the whole flow, plus a synced web dashboard to view and monitor everything.

01

The concept

Existing platforms force people into narrow buckets — food delivery, home repair, digital freelancing — with fixed pricing and no way to post an open-ended need. TaskDrop inverts the model: you post the request, the market comes to you, and price is set by conversation instead of an algorithm.

Dual-mode app

A seamless toggle between Post a Request (User mode) and Find Work (Worker mode) in one account.

Dynamic quoting

Posters set a benchmark price; workers pitch quotes and negotiate directly, in-app.

Browse-first feed

A Fiverr-style browse home — search, category tiles across the 3 pillars, and cards for nearby, recommended, and urgent tasks.

02

Tech stack & how sync works

The core requirement is that mobile and web stay in sync. The cleanest way for a small team is one backend both clients talk to, with realtime built in — so a bid placed on the phone appears on the dashboard instantly, and the reverse.

LayerChoiceWhy
Backend / DBSupabase — Postgres, Realtime, Auth, Storage, Row-Level SecurityOne source of truth with realtime push out of the box; no custom socket server to run.
Android appFlutter (or React Native)Smooth, native-feeling UI; single codebase can add iOS later.
Web dashboardNext.js + ReactFast read-only dashboard against the same Supabase project.
Payments / EscrowRazorpay Route (or Stripe Connect)Escrow-style holds, split payouts, and commission are first-class.
MediaSupabase StorageCDN-backed photo delivery for task media and proof uploads.
NotificationsFirebase Cloud MessagingPush for new bids, messages, and status changes.
Maps / radiusGoogle Maps SDK + PostGISDistance filtering and local-intel geo features.
Masked callingExotel / Twilio number maskingPoster ↔ worker calls without exposing real numbers.
The sync model in one line Both apps read and write the same Postgres tables through Supabase; Realtime pushes every change — new bid, new message, status transition — to whoever is watching. Sync is a property of the architecture, not a feature you build twice.

Exception paths

LOCKED → CANCELLED

Before the worker starts: free within the grace window, otherwise a small flat fee to the worker.

TASK_STARTED → CANCELLED_BY_POSTER

Penalty applies. Poster pays a fee from escrow; the worker is compensated for committed effort.

TASK_STARTED → STOPPED_BY_POSTER

Unlocks only once elapsed time exceeds 2× the agreed duration — the Uber/Rapido-style "this is taking too long, stop" control. No standard penalty.

WORK_DONE / TASK_STARTED → DISPUTED

Poster reports a late / undone / stalling worker. Hits the worker's rating, review, and standing; admin reviews before any refund is finalized.

05

Deal rules, solved the Uber way

Uber's marketplace already answers the hard money-and-timing questions. Each rule below maps what Uber does onto the TaskDrop equivalent.

1 · Pre-start cancellation

Uber: free window, then flat fee

Uber lets you cancel free for a few minutes, then charges a small flat fee once a driver has committed. → Free to cancel within a 5-minute grace window after locking, or any time before the worker slides Start; after that, a small flat fee (₹20–50) goes to the worker.

2 · Penalty after start

Uber: flat — but rides are uniform

Uber's fee is flat because every ride is similar in value; TaskDrop tasks range from ₹80 to ₹40,000, so a flat fee can't be fair. → Take Uber's principle (compensate committed effort) as a percentage with a floor: 20% of the locked quote, minimum ₹50, paid to the worker from escrow.

3 · Auto-release after "Work Done"

Uber: fare auto-settles at drop-off

Uber has no "confirm" step — the fare settles automatically and the rider disputes afterward. → Keep the explicit Work Completed tap, but back it with a net: if the poster neither confirms nor disputes within 24 hours, escrow auto-releases to the worker.

4 · Who sets the agreed duration

Uber: ETA shown before you book

Uber shows an ETA and you accept it by confirming the ride. → The worker states an estimated duration in their quote; the poster sees it before locking, so locking = accepting it. That number drives the 2× stop threshold.

Locked-in defaults

Every number lives in an admin-configurable settings table, not hardcoded — so you can tune per city or pillar as you learn, exactly like Uber tunes fees by market.

RuleDefault
Pre-start cancelFree within 5-min grace or before Start; else flat ₹20–50 to worker
Post-start penalty20% of locked quote, min ₹50, paid to worker from escrow
Auto-release24 h after Work Done → auto-release unless disputed
Overrun stop threshold2× the agreed duration (worker-set, poster-accepted)
Commission8–10% from worker payout + 3% checkout fee from poster

  • Masked phone calls (numbers hidden)
  • Push notifications

Monetization & safety

  • Featured tasks & promoted / boosted task posts
  • Reporting, disputes, admin moderation
  • Full audit trail on money & calls

Open decisions

Two calls left before Phase 1 kicks off. Everything else above is decided.

Mobile framework

Flutter — recommended; smooth, polished UI and an easy iOS path.

React Native — shares a language with the Next.js web build.

Native Kotlin — best performance, no code sharing.

Payments provider

Razorpay Route — recommended; India-first, native escrow & splits.

Stripe Connect — global, limited India domestic support.

Decide in Phase 3 — keep provider-agnostic for now.
