Covered (code read only, no live walk and no sign-in, so no width or theme was run; 16-17 Nov 2026): `HomeScreen` (Earn search results and feed card), `components/HomeSections` (Earn Home), `ExploreScreen` (Find work list, `SearchBox`, `ViewSwitch`), `NearMapScreen`, `components/NearMap`, `NearMapParts` (job card, rows), `MapFilterParts`, `JobsNearHero`, `WorkCard`, `ListingCard`, `BidSheet` (offer form), `lib/mapFilters`, `jobFiltersStore`, `findWorkRead`, `TaskDetailScreen`, `SwipeScreen`, `ActiveScreen`, `MyQuotesScreen`, `SavedScreen`, `SearchScreen`, `OrdersScreen` (with `lib/taskRows`), `StreaksScreen`, `AnalyticsScreen`, `ListingEditScreen`, `DetailSheetScreen`, `IdeasScreen`, `IdeaDetailScreen`, the location hooks (`useLivePlace`, `locationAsk`), and the server code they call (`supabase/functions/api/reads.ts`, `writes.ts`, migrations 015, 136, 140, 148). One read-only `select` on staging counted open tasks (252 open requests: 214 pinned, 38 remote). Nothing was changed outside this file.

## Findings

### S5-1 · "Remote & online" on Earn Home can shimmer forever after one failed read
- Level: Medium · Area: Earn Home (`EarnTop`) · Class: UI · Where: all
- Steps: code path. Open Earn Home; make the poster lookup (`attachPosters`) fail once (offline blip, server 5xx).
- Current: `load()` awaits `attachPosters(rem)` with no catch (HomeSections.tsx:685-688). The rejection is swallowed by `useHomeLoad` (`() => {}`, lines 76-81), `remote` stays `null`, so the section shows a grey shimmer (line 1009-1010) with no error, no retry button. It only re-runs at the next focus tick.
- Expected: an error line with a "Try again" button, or an empty state, like `LoadFailed` elsewhere.
- Proof: HomeSections.tsx:685-688, 76-81, 1009-1010.
- Cause: every other list on that screen has `.catch(() => [])`; this one does not.

### S5-2 · Distance on a card can belong to the wrong job (km taken by index after `attachPosters`)
- Level: Medium · Area: Earn Home "Jobs near", Find work hero strip, full map · Class: Both · Where: all
- Steps: code path. `tasksNear` returns rows with `km`; `attachPosters(rows)` answers "in the same order the caller asked in; anything no longer visible drops out" (reads.ts:271-274); the app then copies `km` from `rows[i]` onto `withPeople[i]`.
- Current: if one task is dropped (closed or hidden between the two calls), every job after it gets the km of its neighbour. Home shows a wrong "x km"; the map and hero count use it for sorting and "nearest".
- Expected: match by id, not by position.
- Proof: HomeSections.tsx:752 (`km: rows[i]!.km`), JobsNearHero.tsx:56 (`km: r[i]!.km`), NearMap.tsx:397 (`from(x.loc_lat, x.loc_lng, r[i]!.km)`; this one recomputes km from the pin when `home` is set, so it is only wrong without a place).
- Cause: positional zip of two lists that can differ in length.
