### L2-1 · Find work search for `' OR 1=1 --` fails with "Couldn't load this" (DB_ERROR)
- Level: Medium · Area: Find work, list search (searchTasks) · Class: Backend · Where: website (all)
- Steps: Earn mode, Find work list, type `' OR 1=1 --` in the search box, press Enter.
- Current: the list shows "Couldn't load this / Check your connection and try again / Try again". The `api` batch returns HTTP 200 with `{"ok":false,"error":{"message":"Something went wrong. Please try again.","code":"DB_ERROR"}}` for the `searchTasksWithPosters` call (captured with a fetch hook). The message blames the connection, which is wrong. Parts of the string alone work (`'`, `' OR`, `' OR 1`, `OR 1=1`, `1=1 --`, `x -- y`, `a=b`, `<img src=x onerror=alert(1)>`), only the whole `' OR 1=1 --` fails, every time (3 of 3).
- Expected: any typed text returns a result list or "No tasks match"; a server error should say so, not "check your connection".
- Proof: live, 16-17 Nov, taskdrop.in, 390 not needed (desktop). Code that builds the filter: `supabase/functions/api/reads.ts:243-244` (strips `,()*%\` only; the rest goes into `.or("title.ilike.%...%")`). Nothing is leaked (the text is not executed as SQL); it is a robustness and wrong-error-message bug.
- Cause (if known): characters other than `,()*%\` still reach PostgREST's filter grammar (likely the `'` plus the `--` or `=` sequence); not isolated further.
